Why it moved

Through most of its life, RadEcho ran on an old ThinkCentre M93p sitting on a home Verizon LTE hotspot. That held up fine day-to-day, but a two-night stretch at the end of July made the cracks impossible to ignore: NOAA fetch timeouts, a Cloudflare Tunnel that kept dropping because the connection itself was unreliable, and — the real culprit — two Wi-Fi interfaces on the same machine fighting over the connection, which caused a roughly 12-hour outage. A first attempt at fixing it picked the wrong interface as primary and made things worse, causing a second, ~16.5-hour outage the following night before it was sorted out for good.

Nothing in that story was RadEcho's own code — it was the hosting. A friend, Tariq, had a spare machine sitting idle and offered it up. RadEcho moved over for good on August 2, 2026. The ThinkCentre is still intact as a cold fallback, but it's retired from active duty.

The box

A Dell Pro Micro Plus, running Windows 11 Pro with Ubuntu Linux inside via WSL2 — that's where RadEcho's server actually lives and runs, same as it did on the ThinkCentre, just on much stronger hardware and a real wired connection instead of a home hotspot.

Survives a Windows reboot on its own A Windows Task Scheduler job keeps the Linux side alive across restarts — genuinely tricky to get right (WSL2 tears itself down the moment nothing's actively holding it open), but confirmed working with a real hands-off reboot test.
🚦
Deploys can't silently ship the wrong thing A new deploy script only ever deploys an exact, named point in git history — never whatever happens to be sitting on a laptop's disk — and runs the full lint/test suite before anything touches the live service. A bad deploy gets stopped before it goes live, not after.

What the extra horsepower buys

RadEcho renders radar images in parallel across a pool of background workers. On the ThinkCentre, that pool was capped at 2, later cautiously raised to 4 — its weaker CPU couldn't safely go further. On the new box, real load tests (not guesses) found the actual ceiling:

23s
4 workers
16s
8 workers
13s
10 workers

Time for 5 friends to load 5 different stations at once, cold (nothing cached). Pushing past 10 workers (tested up to 14) made no further difference — at that point NOAA's own data-fetch speed, not this box's CPU, is what's actually limiting things.

What's shipped since the move

The stronger, more reliable box is what made this run of features possible in the first place — most of it is the kind of thing that's risky to build on hardware that might fall over under real concurrent load.

↻
Auto-refresh Leave a station open and RadEcho quietly picks up new scans on its own — backed by continuous background prefetching that keeps actively-watched stations warm.
🧩
Tile batching ~200 individual image requests per load collapsed to about 7 — loads now appear as one unit instead of visibly popping in piece by piece.
🎞️
Longer, deeper loops Animation length raised from 10 to 20 frames, zoom raised well past its old ceiling — both were previously capped partly out of caution about per-request load.
🧵
A real rendering bug fixed at long range The Native (wedge) style could silently drop a real band of radar data — sometimes tens of kilometers wide — at the edges of a tile, wherever the station sat close to a tile's edge rather than its corner. Root-caused, fixed, and the underlying alignment test tightened so it can't quietly regress.
🎯
A new look Both the browser-tab favicon and a matching logo in the app's own header — new icon, first time RadEcho has had real matching branding.
